# AGENTS.md

Godo is the Go client library for the DigitalOcean API (`github.com/digitalocean/godo`).
It is hand-written: there is no code generator for the main package, so new endpoints
are added by hand following the patterns of the existing services.

## Layout

- `godo.go`: `Client`, `NewFromToken`, `NewClient`, `New`, request/response plumbing
  (`NewRequest`, `Do`, `CheckResponse`, `ErrorResponse`), and `libraryVersion`.
- `<resource>.go` and `<resource>_test.go` at the repo root, one pair per API area
  (`droplets.go`, `kubernetes.go`, `hosted_agents.go`, ...).
- `errors.go`: `ArgError` / `NewArgError` for client-side argument validation.
- `metrics/`, `util/`: small helper packages.
- `examples/`: runnable programs, one `main.go` per directory.
- `scripts/`: release helpers used by the `Makefile`.

## Commands

```sh
go test -race ./...          # what CI runs (ubuntu, macOS, Windows; two Go versions)
gofmt -s -l .                # CI fails if this prints anything
go vet ./...
```

Use `go test -race ./...` rather than `make test`: the Makefile target passes
`-mod=vendor` and the repo has no `vendor/` directory.

## Adding or changing an endpoint

- Define a `<Name>Service` interface, a `<Name>ServiceOp` struct holding `client *Client`,
  and `var _ <Name>Service = &<Name>ServiceOp{}`. Add the field to `Client` and wire it in
  `NewClient` in `godo.go`.
- Methods take `context.Context` first and return `(*T, *Response, error)`
  (or `(*Response, error)` for no body). Build requests with `s.client.NewRequest`
  and send with `s.client.Do`, which returns an `*ErrorResponse` for non-2xx responses.
- Validate required arguments with `NewArgError` before making a request.
- Link the API reference in the interface doc comment
  (`// See: https://docs.digitalocean.com/reference/api/...`). Exported types, fields
  and funcs need doc comments.
- Tests live next to the code. Use `setup()` / `defer teardown()` from `godo_test.go`,
  register handlers on `mux`, check the method with `testMethod`, and call through
  the package-level `client`, which points at a local `httptest` server.

## Generated files

- `apps.gen.go` is generated outside this repo (header says `DO NOT EDIT`). App spec
  changes arrive as a regenerated file.
- `apps_accessors.go` and `apps_accessors_test.go` are generated by gen-accessors.
  Do not hand-edit either.

## Versioning and changelog

Godo follows semver. `CHANGELOG.md` and `libraryVersion` in `godo.go` are updated by
maintainers in a separate release PR (see `CONTRIBUTING.md`). Do not edit them in a
feature or fix PR.
